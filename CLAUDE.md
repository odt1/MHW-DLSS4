# MHW-DLSS4: notes for working on this project

DLSS 4 for Monster Hunter: World (Iceborne, game version 15.2x, tested on 15.23), as a native plugin DLL loaded by Stracker's Loader from `nativePC\plugins`. C++20, MSVC, CMake + Ninja. Current version: see `project(... VERSION ...)` in `CMakeLists.txt` (0.9.5 at the time of writing). Releases are git tags (`v0.8.2`) with the zip attached as a GitHub release; the repo is public on GitHub (`odt1/MHW-DLSS4`). Licence: BSD-2-Clause (`LICENSE`, "Copyright (c) 2026, odt1"), for the project's own code. No copyleft code or licence: the DLSS SDK licence (4e) forbids using the SDK in a way that puts it under terms requiring source release, and the DLL links `nvsdk_ngx_s.lib`.

Called MHWDLSS (`MHWDLSS.dll/.ini/.log`, `MHWDLSS\` folder, repo `odt1/MHWDLSS`) up to 0.7.3; renamed to MHW-DLSS4 in 0.8.0. The ini, log and data folder names follow the DLL's file name. Kept on purpose: the C++ namespace `mhwdlss`, the NGX project id, and the local checkout folder `C:\Projects\MHW DLSS` (Claude's project memory is keyed to that path). If both DLLs are installed, the first one the loader loads (`MHW-DLSS4.dll` sorts first) hooks the game, the other one fails `game::Init` ("TAA vtable not found") and stays inactive, and MHW-DLSS4 logs a warning to delete the old files.

`README.md` is for players and belongs to the user, who rewrote its top part themselves. Keep it plain and non-technical, and don't restructure it without being asked. Developer detail goes here or in `docs/`.

## Layout

```
src/                  the plugin
  dllmain.cpp         start-up: config, log, game::Init, ngx::Install
  game.cpp/.h         game RE: renderer/scene/camera globals, TAA filter hooks, jitter, depth-view
                      fix, anti-aliasing hold, render-scale recompute
  ngx_shim.cpp/.h     replaces the game's NGX 1.x function table; runs current DLSS (TAA and DLISP
                      positions), feature lifetime, optimal-settings callback, ini hot reload
  ngx_params.cpp/.h   the NVSDK_NGX_Parameter object handed to the game
  dlss_dll.cpp/.h     which nvngx_dlss.dll to use (driver store / DLLPath / MHW-DLSS4 folder)
  sharpen.cpp/.h      NVSharpen / Vanilla / RCAS compute passes after DLSS (D3D11 + D3D12)
  reflex.cpp/.h       NVIDIA Reflex through NVAPI: sleep mode, Sleep at the frame start, latency
                      markers, latency report (LatencyStats)
  d3d_util.cpp/.h     texture info, mirror copies, rect copies, D3D12 retire queue, debug dumps
  probe.cpp/.h        DebugProbe / DebugDumpFrames (D3D12 only)
  config.cpp/.h       MHW-DLSS4.ini (default text = kDefaultIni) and graphics_option.ini reading
  crash.cpp, log.cpp, memory.cpp (pattern scan, SafeRead, WritePointer)
  shaders/            nis_sharpen.hlsl, vanilla_sharpen.hlsl, rcas.hlsl (fxc at build time)
third_party/          NIS SDK v1.0.3 (MIT), AMD FSR licence, DLSS SDK (not committed, see its README),
                      nvapi/nvapi_reflex.h (Reflex subset of NVAPI, MIT; sizes checked against nvapi.h)
tools/                build/deploy/package scripts and measurement tools (index below)
  re/                 static RE helpers for the unpacked game exe
  live/               scripts that read/poke the running game or drive test runs
  capture/            graphics debugging: MHW-Capture.dll (RenderDoc from inside the game), rdq.py
images/               before/after comparisons used by README.md
```

Local-only folders (git-ignored, never commit): `re/` (game exe, copyrighted), `graphics/` (raw screenshots, Affinity files), the other loaders and mods (`Stracker's Loader Binary`, `SharpPluginLoader`, `MHW-QuestLoader`, `MHWSS-*`, `Performance Booster and Plugin Extender`), `nvngx_dlss.dll`, `build/`, `dist/`.

## Build, deploy, package

Machine-specific setup is in the user's global CLAUDE.md (pwsh, `devshell` for MSVC, Git Bash).

```
pwsh:  . $PROFILE; devshell; cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
pwsh:  . $PROFILE; devshell; cmake --build build
tools\deploy.ps1       copies build\MHW-DLSS4.dll + .pdb into the game (game must be closed)
tools\package.ps1      dist\MHW-DLSS4-<version>.zip: DLL, default ini (extracted from kDefaultIni in
                       config.cpp), README as MHW-DLSS4-README.md, LICENSE as
                       MHW-DLSS4-LICENSE.txt, THIRD-PARTY notices (NIS, FSR, NVAPI, DLSS SDK)
```

Bump the version in `CMakeLists.txt` for every release. The zip has no `nvngx_dlss.dll` unless `package.ps1 -Dlss <path>`. CMakeLists.txt sets `/O2 /Gw` and `NDEBUG` on the target for every non-Debug build (plus `/Zi /DEBUG` for the PDB): the old `build\` folder had empty cached `CMAKE_CXX_FLAGS_<CONFIG>` (first configured without the MSVC environment), so 0.7.3 and 0.8.1 shipped unoptimised (`/Od`). Check the `FLAGS` line in `build\build.ninja` after a fresh configure. Before changing source, keep a copy of the last released `src/` (the repo is in git now, so a tag per release does the job).

## Game, files, test workflow

- Game folder: `F:\SteamLibrary\steamapps\common\Monster Hunter World`. Launch with `steam://rungameid/582010`. The exe is SteamStub-packed; the unpacked copy for RE is `re\MonsterHunterWorld.exe.unpacked.exe` (Steamless at `C:\Applications\Steamless 0.5`). Image base 0x140000000 (no ASLR), so exe addresses below are absolute VAs; the plugin logs RVAs (+0x...).
- Plugin files in `nativePC\plugins`: `MHW-DLSS4.dll`, `MHW-DLSS4.ini` (hot-reloaded, mtime checked twice a second from the TAA update), `MHW-DLSS4.log`, and the `MHW-DLSS4\` folder (NGX data, `driver\nvngx_dlss.dll` copy, `custom\`). Never put a DLL directly in `nativePC\plugins`: the loader loads every DLL there.
- The user also runs `MonsterHunterFixorld.dll` (their own swapchain/frame-latency/loading plugin; its log shows fps, hitches and `ResizeBuffers` with the swapchain format), `!CRCBypass.dll`, CutsceneSkip, QuestLoader, MonsterLoader. Don't rely on CRCBypass: the plugin patches no game code, only `.rdata` vtable slots and `.data`.
- `graphics_option.ini` (game folder): the game's options. **Never write it with a BOM** (the game then ignores it and starts with defaults: DX11, 1080p). Edit it as ASCII and restore it byte for byte after tests. After a GPU crash the game writes `DirectX12Enable=Off` itself; tell the user.
- Log levels (0.9.4): `LogLevel=Info` (default) logs only what a player needs: load, config, DLSS version, NGX ready, feature created, `evaluate #512 ok` (the sign that DLSS runs), ini reloads, Reflex status, warnings and errors. Everything else (hook offsets, jitter capture, evaluate details and progress, camera, AA/reflection/mip-bias holds, feature create/release by the game, adoption) is `LOGD` and needs `LogLevel=Debug` (hot-reloaded). Developer keys that exist to log (`LatencyStats`, `NGXLogging`, `VerboseFrames`, the probes) stay at Info. Test scripts that need debug lines set `LogLevel=Debug` themselves (`bypassupscale.py`).
- Test runs: launch via Steam, wait for `evaluate #512 ok` in the log (title screen is enough for most checks; getting into the hub needs the user), change keys in `MHW-DLSS4.ini` (ASCII), and end the run with `Stop-Process -Name MonsterHunterWorld -Force`. Never CloseMainWindow (it shows a dialog only the user can answer). Killing a game the user started is fine during active work.
- After a test session, overwrite the user's `MHW-DLSS4.ini` with the packaged default ini of the new version (the user's explicit preference), not with their old one.
- Captures: `tools\capture-window.ps1 -Path x.png` (PrintWindow, no focus steal; works in DX12 and now also DX11 windows, but sometimes returns all-black frames; retry). `DebugDumpOutput=1` writes the DLSS output to `MHW-DLSS4\output.bin` (D3D11 only; `tools\bin2png.py`). `DebugDumpFrames=N` dumps TAA-position colour/motion/depth/jitter (D3D12 only; `tools/motion_check.py`).
- GPU faults: check the System log for `nvlddmkm` event 153 (they come in threes) and the game's `ERR12 : Graphics device crashed.` handler. `tools/live/modetest.py <cycles>` launches the game if needed and switches Mode at run time; it stops at the first driver error, dead game or switch the plugin did not reload. The packaged ini has LF line endings, the scripts keep whichever is there. `bypasstest.py [switches]` checks the AA give-back with Bypass and VRAM across switches; `bypassupscale.py` checks that Bypass in Performance keeps the hold and DLISP running.
- Latency: `LatencyStats=1` ([Advanced]) logs NVIDIA's latency report every 5 s; `tools\live\latencytest.ps1 -Variants 'LowLatency=Off;ReflexSleep=0', 'LowLatency=On', ...` sets keys in the running game and prints one report per variant. Caps of the game's Frame Rate option need a restart with `FrameRate=60` in graphics_option.ini (restore it afterwards). The test machine's NVIDIA profile (global; test changes to the game's profile are reported to the user and deleted again with `nvprofile.py delete frl`): global Max Frame Rate 240 and Low Latency Mode On (pre-rendered frames 1), so light scenes run at 240 fps and the driver always reports low latency mode on once Sleep is called.
- Launching the game rotates the logs of the other plugins too (MonsterHunterFixorld.log and .prev).
- Python: plain `python` has no numpy; use `uv run --quiet --with numpy --with pillow python -I x.py` (`--with capstone` for the RE scripts). In Git Bash heredocs `\\` collapses to `\`: write scripts with the Write tool instead.

## How the plugin works

1. **NGX table.** The game links a static NGX 1.3 library and initialises the driver's NGX core with its application id before plugins load. `ngx_shim.cpp` finds the library's function table (via the `NVSDK_NGX_D3D1x_*` exports' first `mov r64,[rip+x]`) and replaces its 7 entries, re-applying them every frame because the game's init rewrites them. The game's DLSS context (device +0x42700, `game::DlssContext`) gets the plugin's parameter object. **Early load (0.8.1).** With Stracker's Loader alone, plugins load after the game's NGX init and before its DLSS apply. SharpPluginLoader 2.0 (`winmm.dll` proxy, `loader-config.json` "SPL" with PreloadDLLs `dinput8.dll`) preloads Stracker's Loader at sMhMain construction, so the plugin loads before the renderer exists. The game's `NVSDK_NGX_D3D12_Init` export (`0x14273f230`) zeroes the table (`0x1451d8808`..`0x1451d883f`), loads the NGX 1.x core and fills the 7 entries through the exe's GetProcAddress import (slot `0x142e13118`), then calls the Init it got. Left alone, the game set DLSS up with the 1.x core: type 2 (DLISP at 0.75, no DLSS pass), so the plugin had nothing to upscale (grey screen). Calling `RecomputeRenderScale` after a late adoption switched type 2 to 1 mid-run and crashed the render thread: a null texture in a pass binding at `0x14229268b`. So when `game::Device()` is null at install, `HookNgxLookups` swaps that import slot (found from the `FF 15` calls in the Init exports) and returns the shim entries for `NVSDK_NGX_D3D1x_*` names. The game's NGX init then goes through the plugin, the 1.x core is never initialised, and the context is created with the plugin's parameters. The shim Init reports failure without an NVIDIA GPU. After a late adoption, the render scale is only recomputed when the game already has a DLSS pass; otherwise the log says to toggle DLSS.
2. **Current NGX.** The legacy context is shut down (otherwise the driver serves MHW's per-game OTA DLSS 1.2.110 model: zebra garbage, presets ignored) and NGX is initialised with a project id and the folder of the chosen `nvngx_dlss.dll` as its only search path.
3. **Optimal settings.** The game asks `DLSSOptimalSettingsCallback` for the render size; the plugin answers from `Mode` (DLAA 1.0, Quality 2/3, Balanced 0.58, Performance 0.5, Custom 0.5..1) with `DLSSMode=1`. The game clamps render scale to >= 0.5 (UltraPerformance gave a black screen). Ini reloads call the game's render-scale recompute (`game::RecomputeRenderScale`).
4. **TAA position.** The game's DLSS 1 call sits inside the TAA filter's draw (uTemporalAAFilter2). In DLAA, DLSS runs there on colour, dense motion vectors and the R32F depth copy, writing the TAA history texture. In the upscaling modes the TAA position copies the jittered colour through (`CopyRect12/11`) and mirrors motion/depth (`Mirror12/11`) for later.
5. **DLISP position.** In the upscaling modes DLSS runs where the game called DLISP (its old upscaler), after post-processing, on display-referred colour (max about 1.4), with MVLowRes. `StaleFrame` skips frames of the old size after a resolution change.
6. **Sharpening.** With Sharpness > 0, DLSS writes a plugin texture and a compute pass writes the game's target: NVSharpen (NIS linear-HDR mode, strength and limit faded by min(1, s/0.5); 1 = NVIDIA's 0.3), Vanilla (reimplementation of DLISP's "DLSS Sharpen", strength 1.5*s, on sqrt(x/(1+x)), added as a difference), RCAS (FSR 1). All share NIS's root signature. `Sharpness=Game` follows `DLSS_Sharpness` in `graphics_option.ini`.
7. **Jitter.** The TAA update writes the camera jitter only under scene conditions; the plugin forces it on (`ForceJitter`, `EnsureJitter`) and widens it by 2/renderScale (`FullPixelJitter`). DLSS jitter = (0.5, -0.5) * camera jitter * render scale.
8. **TAA sharpen pass** (+0x187) is cleared during the draw while DLSS runs (it would overwrite the DLSS output: DLSS was pointed at history[next]).
9. **DX12 depth view.** The game's DX12 DLSS barrier code reads the depth copy texture's depth-view native (+0xf0), which is null, and crashed; `PatchViewDepth` aliases the colour native (+0x60) there and takes a reference (InterlockedIncrement native+8), because the game releases +0x60 and +0xf0 separately. Without that reference (before 0.7.1) every texture rebuild destroyed the native twice: "exploded geometry" until a restart.
10. **Anti-aliasing hold (0.7.2).** While DLSS runs, the scene's AA switches are held at TAA only (see below), so FXAA never runs after DLSS and Off/FXAA can't switch DLSS off. Released (game value given back) only by Bypass in DLAA or when NGX could not be initialised (`game::SetDlssUnavailable`).
11. **D3D12 retire queue (0.7.2, clock fixed in 0.7.3).** D3D12 frees resources on the last Release even while queued command lists use them. Replaced mirror textures, the sharpen target and released NGX D3D12 features go to `d3d::Retire` / `RetireFeature` and are freed 16 distinct renderer frames later (`RetireTick(game::Frame())` from the update callback). At NGX shutdown only the retired features are flushed (NGX would free them anyway); textures and the sharpen state stay retired. Freeing at once faulted the GPU (nvlddmkm 153, ERR12) on run-time Mode switches. NGX accepts a new feature while the old one still exists. D3D11 releases stay immediate. The motion/depth mirrors are retired as soon as the TAA position runs in DLAA.
12. **NVIDIA Reflex (0.9.0).** `reflex.cpp`, independent of DLSS. NVAPI through `nvapi_QueryInterface` (nvapi64.dll from System32). Once the game's swap chain exists (device +0x1470 D3D12 / +0x1488 D3D11), the plugin hooks its Present (vtable slot 8; under ReShade that is ReShade's proxy vtable, whose Present slot Fixorld had already patched, so the hooks chain) and the exe's SetEvent and WaitForSingleObject imports, and gets the D3D device from the swap chain (ReShade's D3D12 proxy returns the device for `GetDevice(ID3D12Device)`, real DXGI only the queue: both are tried). `NvAPI_D3D_Sleep` + SIMULATION_START at the sMhMain update hook, INPUT_SAMPLE at the mouse update, RENDERSUBMIT_START at SetEvent(start), RENDERSUBMIT_END at SetEvent(done) on the render thread, SIMULATION_END at the main thread's first wait on the done event, PRESENT around Present; render and present ids trail the simulation's by one frame (see the frame pipeline below). Settings: `[Reflex] LowLatency=Off|On|Boost` (default On); developer keys `FrameLimit` (fps, `minimumIntervalUs`; the user dropped it from the player ini because the game's and the driver's caps measured the same), `LatencyStats`, `ReflexSleep`; with LowLatency Off, no FrameLimit and `LatencyStats=0` no NVAPI call is made. Measurements are in docs/technical.md.
13. **Reflection fix (0.9.1).** `HoldReflectionJitterOff` (game.cpp, from the TAA update like the AA hold) keeps the scene's `mSSLRGBufferJitter` byte (+0xb440) at 0 while DLSS runs (developer key `ReflectionFix`, default 1, not in the default ini: the user asked for it to be a debug flag after confirming the fix and no performance cost) and gives the game's value back when the hold ends (Bypass in DLAA, NGX unavailable, DLSS off, key 0). On, the game uses the `_GJitter` screen-space reflection techniques, whose resolve fetches each pixel's reflection history from a neighbour inside its aligned 2x2 block (4-frame cycle from `iRenderFrame`); with the 99.99% history blend the reflections end up nearly constant per 2x2 render-pixel block and change every frame. DLSS scales that up (4x4 screen pixels in Performance): the "pixelated, shimmering" weapon/metal reflections. The plain resolve is the same shader without the fetch offset (RenderDoc diff), so no shader is replaced. Measurements in docs/technical.md (Reflections).
14. **Camera-cut reset (0.9.2).** The game resets DLSS only on a TAA history rebuild (`taa+0x185`, render size change, loading). `CaptureJitter` (TAA pass build) reads the main viewport of `sCamera` once per renderer frame (`CameraCut`) and marks the jitter record `cut` when, since the last frame with a TAA pass, the camera moved > 500 units, turned > 45 degrees or the projection scale changed > 5%; `EvaluateAtTaa` ORs it into `Reset`, the DLISP call inherits it. The log names the main viewport and says when there is none (cut detection off). Developer key `CutReset`.
15. **Jitter phases (0.9.2).** `WidenJitter` writes Halton(2,3) from index 1 with max(20, ceil(8 / scale^2)) phases instead of scaling the game's 20-entry table (kept as is for 20: DLAA, Quality). Developer key `JitterPhases`.
16. **Texture mip bias (0.9.2).** `HoldMipBias` (TAA update) holds the scene's `mSamplerLodBias` (+0x1a8, a sampler bank number) at the bank nearest log2(render scale) - 1 while DLSS runs and gives the game's value back afterwards. Materials bake the bank when they load, so it reaches areas loaded afterwards (set at the title, so the first area has it). Developer key `MipBias` (`Auto`, `Off`, levels). Pure data write, the offset is read from the material resolve (`kSamplerBankPattern`).
17. **NGX failure and no NVIDIA GPU (0.9.5).** NGX is still initialised lazily at the first evaluate. If that fails (the Proton report: `0xbad00001` from `NVSDK_NGX_D3D12_Init_with_ProjectID`, before any nvngx_dlss.dll is loaded), `OptimalSettingsCallback` refuses from then on and `OnUpdate` calls the render-scale recompute: the game then sets scale 1.0 and DLSS type 0 (no DLSS pass, no DLISP), renders at full size with its own TAA and shows its DLSS option as unavailable. Before 0.9.5 the game kept rendering at the DLSS scale with nothing writing the DLISP output: black 3D, working UI. While `SetDlssUnavailable` is set, the jitter widening and the TAA sharpen suppression stop and the AA hold gives the game's value back. Without an NVIDIA adapter in DXGI (and no NGX 1.x core loaded), `AdoptContext` names the adapters in the log and calls `game::Deactivate` (hooks pass straight through). Under Wine both cases log a Proton hint (`PROTON_ENABLE_NVAPI=1`), and the startup log names the Wine version. Developer keys `DebugNgxFail`, `DebugNoNvidia`. Hooks (0.9.5) go through `mem::HookSlot`: the original is stored first, then the slot is swapped by compare-and-swap, retried when another plugin changed it (the scheme of `mem::HookPointer` in the user's FairTransmog and Auto-Auto-Sort plugins, which stay off this plugin's sMhMain update slot `+0x33fa9e8`).

### Threads (0.7.3)

- The TAA pass is built on worker threads, twice per frame and concurrently (two `HookTaaDraw` calls with the same frame and slot on different threads). `OnFrame` (frame callback) therefore only re-patches the NGX table, adopts the context and attaches DLISP, all under the shim mutex. The depth-view alias uses a compare-exchange, and the TAA sharpen flag is cleared by the first concurrent build and restored by the last (`SharpenGuard`).
- The TAA update runs once per frame, also while the TAA filter is switched off, as part of the main thread's sMhMain update: on the main thread almost always, but 0.9.0 testing logged two ini reloads from another thread (a job thread). The update callback (`ngx::OnUpdate`) does the retire tick, the ini and graphics_option.ini reloads (under the shim mutex) and then `RecomputeRenderScale` outside the mutex: the game's recompute releases/creates DLSS features through the shim and the render thread takes the mutex to evaluate. `Install` calls it outside the mutex too. `reflex::Configure` (from the reload) hands its settings over under its own mutex.
- Reflex runs on the main thread (sMhMain update hook = frame start, mouse update, Present, the main thread's SetEvent/WaitForSingleObject); the render thread only sets `RENDERSUBMIT_END`.
- `g_config` is only replaced under the shim mutex; ngx_shim reads it under the mutex (including `OptimalSettingsCallback`). The game hooks read `HookSettings` atomics published by `game::ApplyConfig`. The log level is atomic.
- The game hooks pass straight through until `game::Activate`, which dllmain calls only after `ngx::Install` succeeded.
- `Bypass` means DLAA only everywhere (`Bypassed()` = bypass && !DlispActive()): in the upscaling modes jitter, the AA hold and the sharpen suppression stay on.

## Conventions (measured)

- Motion vectors: clip-space delta * render size; DLSS gets them scaled by (0.5, -0.5) (`MotionScaleX/Y`). Symptom of (1,1): softer, slightly aliased edges only while moving, no ghosting. Verify with `tools/motion_check.py` on a `DebugDumpFrames=8` dump taken while moving (5 s delay).
- Depth is reversed (sky = 0), `DepthInverted=1`. MVs are not jittered.
- Camera jitter h (Halton(2,3), 20 entries at scene+0xe6a0) moves the image by (h.x/2, -h.y/2) * renderScale render pixels (clip offset = h / output size).
- The game passes `Hint.HDR=1`; colour is R11G11B10_FLOAT (fmt 26); DLSS gets IsHDR at the TAA position. DLAA input at the title: median ~0.09, max ~16; the DLISP input is ~10x darker.

## Game RE reference (MHW:I 15.23 exe, absolute VAs)

Globals: renderer `0x1451c4480`, scene `0x1451c4368`, camera `0x1451c4400`, unit list `[0x1451238c8]+0x15d0` (next at +0x30), option gate `[0x1451c5320]+0x2cda` (1 on PC), DX12 flag `0x1451cc080`.

Renderer fields: +0x78 device (device+0x42700 DLSS context, +0x42718 ready, +0x1400 D3D11 context), +0xa5 DLSS on, +0xa6 DLISP on (both only written by the renderer constructor, as 1: the real switches are +0xb4 and device+0x42718), +0xa8 mode (2 = DLSS on), +0xac user sharpness, +0xb0 DLSS scale, +0xb4 DLSS type (1 = DLSS at 1.0, 3 = DLSS + DLISP below 1.0), +0x200/+0x204 render scale requested/applied, +0x1f208 render frame, +0x1f210 frame, +0x1f450 view (+0x58 flags: bits 0x12 / 0x17 skip TAA). Plugin test: DLSS enabled = +0xa5 && (+0xb4 & 1); DLISP active = +0xa6 && (+0xb4 & 2) && scale != 1.

TAA filter uTemporalAAFilter2, vtable `0x14351bda8`: +0x48 update `0x1423931e0` (hooked; jitter when blend +0x180 != 0, type +0xc == 8, flags +0x14 & 0x12 == 0x12, enable +0x184), +0x50 late update `0x142393260` (syncs flag bit 0x2 from the scene TAA switch, clears +0x187 when DLSS is on), +0x60 draw `0x142392150` (hooked; returns early when the scene TAA switch is 0). Fields: +0x168 history[3] (frame % 3), +0x187 mSharpen, +0x198 sharpen amount, +0x1a8 resolved velocity. Camera: +0x38 jitter, +0x40 jitter frame.

uFXAAFilter, vtable `0x14351c1a8`: draw `0x1423939d0` (returns early when the scene FXAA switch is 0), +0x168 input texture.

Anti-aliasing option (`Anti-Aliasing` in graphics_option.ini: Off/TAA/FXAA/TAA+FXAA = 0..3, read from the ini file itself by `0x1404413e0`):
- Apply `0x14043dcb0`: if DLSS is available (`0x1404431f0`), queries the optimal settings (`0x142383ef0` -> the plugin's callback) and maps DLSSMode 1 below scale 1 to TAA only, DLSSMode 2 to TAA+FXAA, DLSSMode 1 at scale 1 (DLAA) to "keep the option". Then the scene setter `0x142287a00` writes the word at scene+0xe9e4 (TAA low byte, FXAA high byte), and the unit loop sets each filter's bit 0x2.
- Runs only when options are applied (start-up, options menu; `0x14043e220` applies the DLSS option and clears the renderer DLSS type via `0x14229bed0` before its AA apply), never on a plugin Mode change.
- The plugin's `HoldTaaOnly` (game.cpp, called from the TAA update every frame) keeps the word at 0x0001 while DLSS runs and gives the game's value back only when the plugin ends the hold itself (Bypass in DLAA, NGX unavailable) and the word still holds the plugin's value (`g_aaOurs`). The setter is pattern-scanned for its offset only, not patched.
- Measured before the fix (DLAA, TAA+FXAA stored): FXAA ran after DLSS (static detail -0.3%, p99 edge change ~4/255); scene TAA 0 skipped the TAA draw and with it DLSS (plain jaggies).

Screen-space reflections (SSLR, from RenderDoc captures; shader names survive in the DXBC): classify -> trace at half render resolution -> resolve `SSLR_Resolve[_Dither][_GJitter][_EachWaterAttn] [_EffectReflection][_FULL_RES]` (compute; 4 random trace samples per pixel, new pattern every frame; outputs the new reflection and the reprojected history) -> blend pass (`CBGlobalIllumination`: history clamped to the 4 neighbours of the new value, kept at `fSpecularTemporalBlendRate` 0.9999, added to the scene, ping-pong history). Technique choice `0x14227ec90(FULL_RES, GJitter, Dither, EachWaterAttn, EffectReflection)` called from `0x142286260` with scene +0xb440 `mSSLRGBufferJitter`, +0xb43f `mSSLRDitherResolve`, +0xb43e `mGlobalEnvMapEachWaterAttn` (names from the property registration in `0x142270c60`; defaults set in `0x1422646f0`). FULL_RES when `0x1425933b0(view+0x630)` == 0: the reflection object (vtable `0x14354d9d0`, constructor `0x1425924d0`) has level +0x228 = 1, scale +0x238 = 0.5 hard-coded, so never; its textures are created from that (`mpTraceMap` +0x108, `mpResolveMap` +0x110, `mpTemporalMap` +0x118). With ScreenSpaceReflection=Off a per-pixel cube-map pass (`tGlobalCubeOnly`) replaces all of it, no history. `tools/live/sslrpeek.py` reads/sets the switches and the level.

Textures: object +0x60 colour native, +0xf0 depth-view native, natives refcounted at +8, released by `0x142554f90` (lock xadd -1, destroy via vtable[0] at 1). Native +0x18 ID3D11 resource, +0x20 ID3D12 resource. Draw context +0x1d0 view, view +0x628 targets, targets +0xa0 depth copy.

Optimal settings query `0x142383ef0` (context, width, height, mode +0xa8): result {1.0, type 0} unless mode != 0, the callback succeeds and its DLSSMode != 0; DLSSMode 1 gives type 3 (1 at scale 1.0), 2 gives type 2. DLSS available (`0x1404431f0`) = option gate && context (device+0x42700) && that query gives type != 0. The options apply `0x14043e220` touches the DLSS fields only with a context. When the game's NGX init fails with `NVIDIA DLSS=On` in graphics_option.ini, the game shows a "DLSS not available" message at startup (seen in the `DebugNoNvidia` test; the text comes from the game's message data, not an exe string) and writes `NVIDIA DLSS=Off`.

Game DLSS 1 details: DLISP (`nvngx_dlisp`) maps NGX "Sharpness" to clamp(0.75*(S-1), 0, 1.5), so the stock 0..1 slider did nothing; the game sets Sharpness only on the DLISP evaluate. The game's DLSS 1 call sets "MV.Scale.X/Y" = 1.0. Fatal GPU handler: `0x1423a9cf0` -> GetDeviceRemovedReason -> "ERR12 : Graphics device crashed." -> writes 0xdeadbeef to address 0 (`0x1421fd0c9`).

Frame pipeline (observed in BN, confirmed by the Reflex markers' timing):
- Window thread `0x1422e4670`: timeBeginPeriod(1), PeekMessage loop with `Sleep(1)`. The game's main thread proc `0x1422e4ae0` loops `sub_14229b020(renderer)` (device checks) and then the main object's vtable +0x30, while the window is active (else `Sleep(1)`).
- sMhMain (vtable `0x1433fa9b8`, base sMain vtable `0x1435072f8`; instance at [`0x1451c4148`], inferred from the timer fields other code reads there) update +0x30 = `0x141af2b60`: `0x14225f1d0` (job sync), `0x14225f9f0` (frame timer and the Frame Rate limiter: `Sleep(ms - 1)` when 2+ ms remain, then a QPC spin; +0x58 base fps, read 60.0; +0x5c target fps, read 300.0 with No Limit), then `0x142293280` (render frame +0x1f208++, maps per-frame buffers, sets +0x90 in flight, `SetEvent(renderer+0x1b8)` when +0x93), then the systems' updates (vtable +0x30 each; sMhMouse `0x140489800` -> sMouse `0x1422e89a0` -> `0x1422e9270`: GetCursorPos + DirectInput `GetDeviceState(0x14)`), then `0x1422980b0`: wait for the render thread (`0x14229cbf0`, `WaitForSingleObject(+0x1c0)`), swap draw data, `0x1423a7f50`, Present `0x1423aa290` (D3D12: `0x1423a9ce0` waits for the fence of the frame two back, then `Present(sync, ALLOW_TEARING << 9)` on device+0x1470; D3D11 on device+0x1488).
- Render thread proc `0x14229aba0` ("Rendering Thread", id at renderer+0x1b0): waits on +0x1b8, builds and submits (`0x142293480`, `0x14229cee0`, `0x14229cd20` with "RenderingSub Thread"s), `SetEvent(+0x1c0)`. Reflex markers: render thread busy ~0.5 ms; the frame's GPU work only ends ~one GPU frame after its Present, i.e. the command lists reach the GPU at the end of the next main thread update.
- So frame N is presented at the end of update N+1, and a wait anywhere on the main thread lands in some frame's input-to-screen time. The game's limiter (before input) and Reflex's sleep cost the same; sleeping after the render thread start was no better (and halved the frame rate with Boost).
- Frame Rate option apply `0x14043e160` (also inlined in `0x14043e220`): writes only sMain+0x5c = 30, 60, 90, 120, 144, 165, 240 or 300 (No Limit); constructor default 3000. sMain+0x60 (fixed step at +0x58 fps, SwitchToThread spin) and +0xd0 (job threads; +0xcc > 1 selects the parallel branch of the update) have only reflection setters (`0x142260240`, `0x142260280` from `0x14225d5d0`).
- Input: all polled fresh in the systems' updates after the limiter. Keyboard singleton `[0x1451c53b0]` (sKeyboard vtable `0x143511f18`, sMhKeyboard `0x142f86d08`), update +0x30 `0x1422e74f0` -> `0x1422e7ad0`: DirectInput keyboard `GetDeviceState(0x100)` mapped scan code -> VK, or GetAsyncKeyState for all VKs without the device; key repeat 500/100 ms on sMain+0x38 (ms clock). Pad: XInputGetState from `0x1422a5710` / `0x1422a59d0` (sPad, vtables near `0x14350dd68`; sMhPad near `0x1433fc580`).
- BetterInputs.dll (2020 Stracker plugin) patches `0x1411edc90` (called from `0x141230bb0`): a per-action input buffer whose window counts down both in time (+0x10 -= dt) and in frames (+0x14 -= 1 per call), so buffered inputs expire sooner at high frame rates; the mod's replacement adds conditions on player state (+0x76b0 -> +0x9f8, +0x6274, +0x6278). It changes buffering, not when input is read.

Camera: `sCamera` `0x1451c4400`, +0x38 jitter, +0x40 jitter frame, 8 viewports at +0x50 (0x1a0 each: +0x18 own target, +0x20 active, +0x25 pass, +0xa0 view, +0xe0 proj, +0x120/+0x160 previous copies; row vectors). Camera update (vtable +0x30, `0x14228eb60`) copies current to previous, then computes the new matrices; camera draw (`0x14228e770`) runs the camera setup `0x14228f3b0` per active viewport and then that viewport's scene pass `0x1423c3790`. Jitter: TAA update `0x1423931e0` -> setJitter `0x14228f390` with the scene table entry `0x14227db60` (frame % 20, scene +0xe6a0 = Halton(2,3) indices 20..39 minus 0.5).

Sampler banks: built once at shader package load (`0x1423d6690`, 15 banks of 63 samplers at `[0x1451c73d0]+0x2488`): 0 no bias, 1..7 -log2(2, 2.5, 3, 3.5, 4, 4.5, 5), 8..14 positive; dynamic resolution groups use log2(level) + log2(0.5). Material resolve `0x142383400` reads scene +0x1a8 (`mSamplerLodBias`) for the first 12 samplers (`0x142383566`).

Render scale paths: with DLSS the options apply (`0x14043e04a`, `0x14043e424`) calls `0x14229bed0` (stores scale and type at +0xb0/+0xb4, +0x200 = clamp(+0xc4 * scale, 0.5, 1), no rounding). The 16-aligning setter `0x14229be60` is only referenced from the renderer's property table. The renderer constructor `0x142290880` stores scale 1.0 and type 0 at +0xb0. The ini reload recompute `0x14229a8c0` asks the context's optimal settings again and stores scale and type the same way.

DX12 pacing: main thread proc -> `0x14229b020` -> (DX12) `0x1423ade30`: WaitForSingleObjectEx(frame latency waitable object device+0x10f0, 1000 ms) unless latch device+0x10da (set by one timeout, never cleared); `SetMaximumFrameLatency` at `0x1423a6553`. Pass order (other mod's notes): bloom before TAA; DOF, motion blur, tone mapping, FXAA before the DLISP point.

Driver DLSS store: `%ProgramData%\NVIDIA\NGX\models\dlss\versions\<(maj<<16)|(min<<8)|patch>\files\
<id>.bin`; MHW's own OTA entries are app B9D2F5C (DLSS 1.2.110), the NVIDIA App override build is
app E658700; `models\nvngx_config.txt` lists versions. The plugin copies the newest >= 3 to `MHW-DLSS4\driver\nvngx_dlss.dll`.

- `tools/re/` (run on `re\MonsterHunterWorld.exe.unpacked.exe`): `strfind.py` (strings + VA), `ripxref.py` (RIP-relative refs), `ptrfind.py` (absolute pointers, vtables, tables), `callfind.py`, `funcroot.py` (function start via chained unwind info + callers), `dis.py` (capstone, `--func`), `qdump.py` (qwords with string resolution), `dispfind.py` (instructions with a given displacement), `funcdiff.py` (compare plugin builds function by function via PDB symbols from `llvm-pdbutil`), `fatbin_ptx.py` (PTX from CUDA fatbins, used on nvngx_dlisp). rizin also works on the unpacked exe (`pD len @ addr`; `af`+`pdf` fail on big functions); in Git Bash call `rz-bin.cmd` etc. (the shims are .cmd).
- `tools/live/` (ReadProcessMemory/WriteProcessMemory on the running game): `aapeek.py` (AA switches, filter flags, renderer DLSS fields), `aa_ab.py` (toggle a switch and capture), `natpeek.py` (texture natives and refcounts), `campeek.py` (camera), `modetest.py` (run-time Mode switch test), `bypasstest.py` (AA give-back + VRAM leak check), `bypassupscale.py` (Bypass in Performance keeps the hold), `titletest.ps1`, `abmulti.ps1` (multi-frame A/B captures), `specshift.py`, `jitregion.py`, `blocky.py` (dump/capture analysis), `latencytest.ps1` (NVIDIA latency report per ini variant), `sslrpeek.py` (SSLR switches).
- `tools/capture/` (documented in docs/technical.md, Graphics debugging): `MHW-Capture.dll` loads RenderDoc from `nativePC\plugins` (SPL early load, before the device exists); `echo 1 > nativePC\plugins\MHW-Capture.trigger` captures. Under RenderDoc the game's NGX setup fails and the game writes `NVIDIA DLSS=Off` into graphics_option.ini: restore it. `rdq.py --start X.rdc` keeps a capture open in qrenderdoc's Python (`rdserver.py`), `rdq.py script.py` queries it, `texio.py` loads texture dumps. RenderDoc 1.46 is installed (winget); its first-run analytics prompt blocks scripted runs (switched off in `%APPDATA%\qrenderdoc\UI.config`). Launching the exe through any debugger fails because the Steam DRM stub restarts it through Steam. Nsight Graphics 2026.3 can capture NGX (`ngfx-capture`), but its captures need the GUI.
- `tools/live/mhwharness.py` (documented in `tools/live/HARNESS.md`): `to-game` gets from a cold start into the world, player controllable, in about 42 s without a human (offline dialog: Space, menus: F, never R/N on the save screen); `pos`, `state`, `key`/`hold`/`mouse`, `react KEY` (key press to player movement, ms), `kill`. Player position `[[0x14500eca0]+0x58]+0x160`. `tools/live/latencymatrix.ps1` runs one restart configuration (game Frame Rate option, driver Max Frame Rate, `-Dx11`) with ini variants through `to-game` and `react`; `-Restore` puts graphics_option.ini and the driver profile back. `tools/live/nvprofile.py get|set|delete frl` reads or changes the driver's Max Frame Rate in the game's NVIDIA profile (takes effect at game start).
